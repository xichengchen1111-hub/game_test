# 昼夜与自动照明 · 实际游戏验证

Unity 6000.3.18f1 / Windows D3D11，播放器为 `builds/windows/TownDemo.exe`。`day-night-comparison.jpg` 由同轮真实 1080p 截图并排排版，未改变画面亮度。`1080/`、`720/` 保留原生游戏截图、状态记录和窗边移动回放；`night-tower/` 是午夜开始后走完整座钟楼的画面。它们不是概念图。

## 已实现

- 复用准确怀表时钟，7 秒推进 10 游戏分钟；不中断时一昼夜 16 分 48 秒。天空、日／月光、三色环境光与雾色同步渐变；午夜连续，暂停和读档跟随原时钟。美术轨道采用 06:00/18:00 地平线，未计算真实地点与冬季天文日出日落。
- 6 盏路灯、2 盏店外壁灯及背景窗户暖光在自然亮度足够时关闭，灯泡发光同步变化。牛奶屋 3 盏与钟表铺前堂 2 盏白天关闭；后部维修照明和钟楼深处保留必要光线。
- `daylightAccess` 按已有窗洞和房间深度设置，计算只使用自然亮度，避免灯具自身亮度造成开关反馈；不是实时照度测量。连续曲线使灯光与发光材质一起渐变。阅读灯手动停用优先；启用表示允许采光不足时亮起，白天仍受自动熄灯控制。
- 共用生成器绑定灯具，同一建筑内外保持一致。只有 1 盏太阳／月光方向灯与原有 2 盏钟表铺阴影点光；牛奶屋及钟楼灯仍无实时阴影。没有逐帧 GI、反射探针重绘或房间射线。塔钟圆形裁切保持，加入微弱夜间表盘补亮。

## 本轮结果

最终同一构建 11 项 PASS，时间和日志路径见 `acceptance.json`：昼夜 1080p、720p、新进程读档；牛奶屋与其读档；时钟与其读档；钟楼、午夜钟楼与上层读档后下楼；钟表铺。共享布局生成检查也通过，并保留错误门窗的拒绝检查。

昼夜检查含完整曲线边界、真实时钟跨过日出／日落／午夜、实际 UI 暂停、发光与照明一致、白天外灯和亮房间熄灯、暗房间照明，以及阅读灯手动关闭后入夜不反开。新进程恢复准确累计时间、牛奶屋位置、阅读灯关闭和订单所选日期。

北窗正午、南窗深夜各用真实控制器横移约 0.94m，13 帧／10Hz，在普通阴影与 AO 下逐帧检查。两种分辨率跟踪窗框亮度范围约 .017–.019，包含木纹和视角变化；指标见 `window-motion-results.json`，原始帧留在本地并忽略 Git，MP4 保留。这不能证明所有场景和显卡彻底无闪烁。牛奶屋墙面的大块黑色是原有奶牛花纹贴图。

`save-isolation.json` 确认正式存档前后 SHA256 相同。历史订单、证物、钟楼 +30 分钟差值和原有门状态保持。

## 复现

在仓库根目录运行 Windows 播放器，分别传入：

```text
--review --fresh --review-day-night -screen-width 1920 -screen-height 1080
--review --fresh --review-day-night -screen-width 1280 -screen-height 720
--review --verify-day-night-save
--review --fresh --review-clocktower --night-illumination
```

可加 `--capture-dir <目录>` 和 `-logFile <文件>`。使用独立 review 存档；读档检查接在对应新开局检查后，用不同播放器进程运行。先关闭其他播放器窗口，避免两个进程同时写同一 review 档。

本轮是程序驱动真实控制器、普通射线和现有 UI 处理器，并目视实际帧；不是物理键鼠或玩家盲测。宿主为 RTX 5060 Laptop GPU，未做低配硬件帧率基准或 Mac 重建，功能通过不能当作低配 60fps 证明。
