# 共面闪烁（z-fighting）全面检查与修复（2026-10-12）

用户要求「修一下所有 Z fighting 闪烁，你来找一下」。本目录是最终构建场景的自动扫描结果。

## 怎么找

`game/Assets/Editor/ZFightScan.cs` 打开 Town、OtherTown、ClockShop 三个生成场景，检查全部 MeshRenderer（LOD0）。判定标准如下：

- 两个三角形朝向相同，较小者的顶点离较大者的平面不超过 2mm，重叠面积不小于 1cm²。
- 两者材质、贴图坐标或光照层不同，即着色会不同。完全相同的面叠在一起不会闪，不计入。
- 门、抽屉、钟针、车轮等运动部件按制作姿态检查，单独记为 MOVING。蒙皮人物不在检查范围内。
- 偏移不超过 0.5mm 记为 EXACT（会闪）；0.5–2mm 记为 near。

运行方法：

```
Unity -batchmode -quit -projectPath game -executeMethod ZFightScan.Run -logFile <log>
```

## 结果（最终 staging 构建 build-z8）

| 项目 | 数值 |
| --- | --- |
| 三角形 | 10,578,789 |
| 渲染器 | 8,050 |
| EXACT（静态） | 0 |
| MOVING（运动部件制作姿态） | 0 |
| near（0.5–2mm） | 496 组 |

near 组大多是修复后有意留下的 2mm 档。深度附件格式为 Auto（URP 桌面默认 32 位浮点、反向 Z），近裁剪面 0.08m；360m 处深度分辨约 0.03mm，2mm 远大于此，不会闪。逐组明细见 `scan.txt`（EXACT／MOVING 在前，按面积排序）与 `scan.json`。

## 回归

原生 Windows／D3D11，全部使用独立 review 存档，`regression.txt` 有逐项结果。以下各项都通过，且都加做了独立进程读档：

- 警署 1920×1080 与 1280×720
- 钟楼、旅馆用车、车站售票员、牛奶店门
- 地图导航、钟表铺、昼夜、全图

车站／列车第一次没过，原因是警署的 E08 副本让检查脚本找到两份 E08，与修闪烁无关。修正脚本后重跑通过。正常存档前后哈希不变。

正常版 `builds/windows/TownDemo.exe` 的修补网格与跑完整回归的构建逐字节相同，仅两处文件改名；游戏程序集与重跑铁路检查的构建相同。正常版上另做了警署冒烟检查，也通过了。

## 局限

- 只检查共面重叠。运动部件只查制作姿态，开到一半时与别的物体偶然共面没有穷举。
- 小于 1cm² 的重叠不报告。
- 这是几何扫描加原生回归截图检查，不是逐帧肉眼巡检全镇，也不是物理键鼠测试。
