# 检票处细化与车门修复 · 2026-10-10

当前 Windows 构建将 B 站票房补成落地木柜、绿色嵌板、黄铜窗格、开放式拱形验票口、实体门头与檐线；票柜有下柜、抽屉、搁板和落在搁板上的票册。收票盘、台铃、账本、墨水盘、检票钳均校准接触面，两盏绿罩工作灯的实体底座、支架、灯罩和暖光来自同一生成源。售票员仍沿用原简化模型。

废票桶从底板到上层纸堆填入废纸，八张分散的旧票分别由纸折支撑。每张保留三个真实穿透孔和透明票面，随身 E02 无孔；没有添加新证词、日期、班次或对历史行程的结论。

旧车门会重复调用“全部打开”，平台侧原本已开，另一侧的旋转角却为零。现改为八扇实体门各自 E 开关、向外转动、动态“打开／关闭车门”提示和单个随门轴移动的叶片碰撞。动画按实际门状态发车关闭，不把已关的门先打开。门扇与真实玩家胶囊相交时退回打开状态；显式暂停冻结普通门动画。停靠初始化平台侧开、另一侧关，手动门状态目前不独立保存。

`acceptance.json` 是本次最终构建的汇总。六项同程序集原生检查通过：1080p／720p 完整检票处近景、21 处字牌的贴面与字号变化、售票员／检票钳／桶标牌普通 E 射线、两侧车门开关及占位防夹、两镇登车发车往返；两种分辨率的独立进程到站读档；59 座休息椅、8 项物品、2 处车灯开关及其读档。`edit-results.xml` 为 32 项通过的 EditMode 检查，包含对悬空票册／检票钳／招牌／支柱、缺失桶内填充的故障注入，以及八扇门的实际开关碰撞和胶囊检测。

`1080/` 与 `720/` 是原生 Unity 帧；`blender-office-oblique.png` 是重开可编辑源后的建模预览，二者不混称实机。`preservation.json` 比较了检票区域之外 207175 个面（保留重复计数）、材质和 UV，坐标精度 0.1mm、UV 精度 0.00001，前后相同。列车 `.blend`／FBX 未重导出、哈希不变。正常档在重开游戏之前与最新退出备份相同；未清零、回滚或重算两小时昼夜的累计分钟。

检查使用程序驱动的真实 CharacterController 和普通三米 E 射线，照片的机位／时间／天气经过布置；不是物理键鼠、玩家盲测、低配或 Mac 验收。未重跑未改变的全镇六种调查顺序，不把既有剧情时间窗口未满足的结果写成通过。原始日志、失败迭代、正常及 review 存档备份位于忽略的 `builds/review/ticket-checkin/`。

Antigravity 仅在 scratch 做旧模型支撑与交互遮挡的只读审计；第一次读文件被拒，第二次成功。数值与结论由本地源码和实机核对，最终造型、实现与验收在本项目完成。其审计保留在 `support-audit-antigravity.md`，不是所有推测已被实机证实的报告。

重建模型与游戏：`tools/BuildRail.ps1 -StationOnly`。只导出模型：再加 `-AssetsOnly`。共享生成源为 `tools/rail/ticket_office.py`；接触数据在 `assets/source/rail/ticket-office-geometry.json` 与 `game/Assets/Resources/TicketOfficeGeometry.json`，必须一并更新。完整铁路生成器也包含此票房，不能手改生成后的场景或另做一套票房。

两个原 review 存档已恢复并逐字节核对。更新后的正常游戏已用原入口在 1600×900 窗口打开，窗口响应、日志确认原正常存档路径、无异常，启动后正常存档仍同哈希；没有 review／fresh 参数或传送。`normal-launch.json` 为启动记录，用户从菜单继续原进度。
