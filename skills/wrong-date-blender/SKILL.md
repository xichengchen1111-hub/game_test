# Wrong Date Testimony low-poly assets

Locate the active repo and read `docs/mvp-demo.md`. Inspect the existing three `docs/concepts/*-low-poly.png` images before establishing proportions or a new visual variant. The images are concept targets, not a promise of complex geometry.

## Asset choices

- For the selected A / Walnut Heritage watch shop (2026-10-08), use `assets/source/watch-shop/reference-walnut.png` and the original editable joinery kit, not the earlier primitive shop. Keep dark green paneled frontage, walnut cabinets, clear glazing, warm light and the locked seated owner. Preserve named door / vitrine / drawer pivots and explicit surface UVs. Runtime shell and doors come from BuildSlice.Walnut; ArchitectureReference in the complete .blend is excluded from FBX to avoid duplicate walls. Circular shop dials use HeritageDial geometry, never opaque square dial backgrounds.

- Keep broad flat color, gray-blue/purple shadows and warm window/interior light. Reuse a small wall, door, window, floor, desk and cabinet kit across scenes. Prefer silhouette, palette and authored surface decoration over extra geometry.
- The milk-delivery child uses the user's 2026-10-11 approved Tripo v5 model, superseding the earlier Meshy default. Keep the packed editable source at assets/source/milkboy/tripo and the importer tools/import_tripo_milkboy.py. Both clips use upright neck/head poses with a 14-degree upward base gaze and about 3-degree restrained side glances; refine with tools/milkboy_raise_gaze.py. Two Humanoid clips: 02_Nervous_HoldShoulderStrap (both hands grip the chest shoulder strap, not the bag lid) and 01_Talk_WithMouth. Preserve correct isolated hand/cloth/strap weights, 68 bones including Jaw, in-place loops and E04. Mouth motion is generic, not audio/phoneme sync. Retain older Meshy/Toon Boy sources and the independent clockmaker.
- Preserve 1931 prop context while carrying over the reference images' lived-in warmth. Modern neon signs and electronics from the reference do not automatically belong in the setting.
- The user requested a Tripo replacement watchmaker on 2026-10-11. Keep the original Tripo export and old Meshy source. tools/build_tripo_watchmaker.py authors the 56-bone Unity-named rig after Tripo's automatic humanoid rejection, isolated apron weights, hand-skinned watch/tool and three seated low-head clips (RepairScrew 8s, InspectMovement 9s, AdjustParts 8s). Keep the packed source in assets/source/watchmaker/tripo. The runtime shuffles all three without adjacent repeats, and freezes only for explicit pause. Keep the 1.72m rest height and .40m seat; measure new soles/support rather than applying the old crossed-leg hip offset. Check tool contact and apron/hand deformation throughout actions and transitions; both shop instances share the same prefab and original dialogue/E07.
- Dates, clock hands, ticket holes and text must be precise. Author typography and clock geometry deterministically; ImageGen can supply surface decoration and style variants but its generated text cannot be a factual clue asset.
- Use meter-scale conventions, useful pivots (door hinge, prop base), explicit material assignments and consistent export transforms. Keep editable `.blend` sources and named collections separate from FBX output. Use simple Unity colliders rather than exporting every visual mesh as a convex collider.

## Scripted production and verification

The 2026-10-09 milk-shop A kit lives in `assets/source/milkshop/interior-a/MilkShopInteriorA.blend`, generated by `tools/milkshop/`. Preserve original non-window meshes and exclude `Reference_ExistingShop_NOT_EXPORTED` from exports. The original Windows mesh was specifically corrected after reported flicker: use shared `assets/source/milkshop/tools/window_joinery.py`, 5cm return overlap, 7cm projection each side, butt crossbars, and single double-sided glass panes. Keep the real wall apertures/colliders. Use cream enamel/brass pendants and reading lamp, a named green ledger/reading rest, bell and bottle tag. Typography is deterministic. Retain metre markers and useful origins; do not use a second building mesh to add furnishings.

Milk doorway upper corners also had a coplanar inner lintel/wall face and overlapping post/header. Use shared `assets/source/milkshop/tools/door_joinery.py`: 8cm inner projection, posts ending at2.727m, lintel bottom2.730m, 3mm butt gap, existing exterior face and opening width. `tools/milkshop/fix_door_joinery.py` is a one-time migration of the three old Trim components, not a general generator to rerun on already repaired sources. Preserve all other Trim face/UV/material signatures, non-Trim meshes, window repair and every collision proxy; save/reopen and verify `verification/door-joinery-repair.json`. Check actual inside upper-corner motion in Unity, not only the controlled Blender render. Source .blend/FBX hashes change, so historical whole-source or original Trim identity claims no longer describe the final asset.

Check the actual Blender executable version; the current Mac has Blender 4.5.9 LTS; do not assume a previous host's version. Prefer `blender.exe --background --python-exit-code 1 --python asset_script.py -- [task arguments]` for deterministic asset generation. Set the Python exit code before the script so exceptions produce a failing process result. Verify current operators with the installed `--help`, `bpy` API or official Blender docs before adding a pipeline dependency.

Read task parameters instead of hardcoding an unrelated project's object names. Write only the intended generated collection/assets; preserve existing source objects and user edits. Re-running a generator must not duplicate the kit or alter exported names unexpectedly.

After generating or changing assets, open the resulting `.blend` programmatically to inspect dimensions, origins, material assignments and object counts, and make rendered review captures. Then verify Unity import size, materials, door clearance and player-height views; a successful FBX export is not sufficient. Keep screenshots and concept art clearly distinguished.

Deliver editable sources, imports and the smallest useful asset manifest. Use visual review to assess the palette and simplicity rather than treating polygon counts as proof of style.

## D police station (2026-10-12)

`tools/police/build_police_station.py` (Blender 5.2 here) reads `assets/source/police/police-layout.json` and writes the packed `PoliceStation.blend`/`.fbx` plus `police-build-manifest.json` (leaf hinges, drawer fronts, material list). Object names are the Unity contract: `Ext_*`/`Int_*` shells, `Glass`, `Leaf_<opening>_<n>` with origin on the hinge, `Drawer_<n>`, `Furn_<id>`, `Lamp_<id>`/`Bulb_<id>`, `EastMarker`/`NorthMarker`. Faces are added with an intended normal and re-wound to match it (u() mirrors), UVs are metric per material. Wall apertures use the column cut shared with Unity colliders, so stacked window/door openings never fill each other. Textures/sounds are original stdlib output of `tools/police/make_police_assets.py` (run on the Mac mini). Check `output/demo/police-station/blender/preview-*.png` and the native frames before accepting changes.
